# Skell EQ release coverage addendum — 2026-11-18

## Selected project and rationale

**Selected: Skell EQ (skell-eq-vst), Windows x64 VST3 release-validator hardening.**

This is a different plugin from the preceding Skell Delay selection. EQ was chosen over another pass on Key or Maw because its existing combined release branch had an independently downloadable Windows VST3 preview and green exact-head package/state tests, but a source audit found a concrete standards-compliance defect in the release metadata normalizer: Python's default json.loads silently accepts duplicate object keys and non-standard NaN, Infinity, and -Infinity values. It can also convert a syntactically valid exponent such as 1e999 into an infinite float unless parse_float is guarded. These behaviors could allow ambiguous module identity fields or non-finite values to pass a gate described as strict JSON.

Candidate checks before selection:
- **Skell Key:** current installer-test safety PR #12, exact-head Windows run #44261809007 passed. Ecosystem Development had just selected Key for that implementation; its open release chain remains intact. No Key branch was edited.
- **Skell Maw:** installer/metadata PR #9 exact-head Windows run #44247697236 passed, but Maw already has a seven-plugin preview and its next important gate is owner-side FL Studio acceptance. No Maw branch was edited.
- **Skell Silence:** active work is its existing release/rollback branch and the shared ledger chain; no product-source change was made there in this run.
- **Skell Delay:** the previous Release & Launch selection; its PR #12 is preserved and no Delay branch was edited.

Extended the existing focused draft PR #11 branch:

- Exponent-overflow correction: 24df947b676bbbb98356c755c2b09c5f1d8b2b98
- File: scripts/normalize_vst3_moduleinfo.py

The normalizer now:
1. Uses parse_constant to reject NaN, Infinity, and -Infinity.
2. Uses parse_float plus math.isfinite to reject exponent overflow such as 1e999 and -1e999.
3. Uses an object_pairs_hook to reject duplicate keys at every object depth.
4. Runs strict parsing and identity validation before writing normalized metadata.
5. Factors file normalization so tests can assert rejected source files remain byte-for-byte unchanged.
6. Extends the workflow self-test with valid escaped-string/trailing-comma fixtures, non-standard constants, positive/negative exponent overflow, top-level and nested duplicate keys, and no-write-on-invalid cases.

No DSP, UI, presets, plugin identity/CIDs, parameter/automation IDs, APVTS state schema or saved host state changed. PR #11 remains draft; no merge or release occurred.
