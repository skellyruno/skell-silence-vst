# Skell EQ release coverage addendum — 2026-11-18

## Selected project and rationale

**Selected: Skell EQ (skell-eq-vst), Windows x64 VST3 release-validator hardening.**

This is a different plugin from the preceding Skell Delay selection. EQ was chosen over another pass on Key or Maw because its existing combined release branch had an independently downloadable Windows VST3 preview and green exact-head package/state tests, but a source audit found a concrete standards-compliance defect in the release metadata normalizer: Python's default json.loads silently accepts duplicate object keys and non-standard NaN, Infinity, and -Infinity values. That could allow ambiguous module identity fields or non-standard values in otherwise unrelated metadata to pass a gate described as strict JSON.

Candidate checks before selection:
- **Skell Key:** current installer-test safety PR #12, exact-head Windows run #44261809007 passed. Ecosystem Development had just selected Key for that implementation; its open release chain remains intact. No Key branch was edited.
- **Skell Maw:** installer/metadata PR #9 exact-head Windows run #44247697236 passed, but Maw already has a seven-plugin preview and its next important gate is owner-side FL Studio acceptance. No Maw branch was edited.
- **Skell Silence:** active work is its existing release/rollback branch and the shared ledger chain; no product-source change was made there in this run.
- **Skell Delay:** the previous Release & Launch selection; its PR #12 is preserved and no Delay branch was edited.

- File: scripts/normalize_vst3_moduleinfo.py

The normalizer now:
1. Uses parse_constant to reject NaN, Infinity, and -Infinity.
2. Uses an object_pairs_hook to reject duplicate keys at every object depth.
3. Runs both strict checks before writing normalized metadata.
4. Factors file normalization so tests can assert rejected source files remain byte-for-byte unchanged.
5. Extends the existing workflow self-test with valid escaped-string/trailing-comma fixtures, all three non-finite constants, top-level and nested duplicate keys, and no-write-on-invalid cases.

No DSP, UI, presets, plugin identity/CIDs, parameter/automation IDs, APVTS state schema or saved host state changed. PR #11 remains draft; no merge or release occurred.
